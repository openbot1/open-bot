## 2. Mới trong v1.07

### 2.1 JSON Canonicalization Scheme — RFC 8785 (`a2a/canonical.ts`)

`canonicalJson()` cũ trong `signing.ts` (sắp key + `JSON.stringify`)
gần đúng nhưng chưa phải RFC 8785. Bản mới:

- Số theo đúng ECMAScript `Number::toString`; `-0` → `"0"`.
- Chuỗi escape mọi ký tự điều khiển, `"`/`\`, và **lone surrogate**
  thành `\uXXXX` (JSON.stringify để nguyên lone surrogate → hai
  implementation ký khác nhau).
- Key sắp theo UTF-16 code unit; `undefined`/function/symbol/bigint/
  NaN/±Infinity/circular → **throw** thay vì lặng lẽ bỏ qua (bỏ qua
  làm hai nội dung khác nhau cho cùng một chữ ký).
- `signing.ts:canonicalJson()` giờ delegate sang JCS (giữ tên + chữ
  ký cũ — code cũ không đổi); `jws.ts` ký payload bằng JCS.

### 2.2 Agent Card ký bằng JWS compact — RFC 7515 (`a2a/cardJws.ts`)

Dạng ký CHUẨN bên cạnh `card.signature` kiểu cũ (giữ nguyên để
backward-compat, cùng một key, cùng một card):

```
BASE64URL(header) "." BASE64URL(payload) "." BASE64URL(signature)
header:  { "alg": "EdDSA", "typ": "agent-card+jwt", "kid": <fingerprint> }
payload: toàn bộ Agent Card (không gồm `signature`) + iat + exp (mặc định 24h)
```

Payload serialize bằng JCS trước khi base64url. Verify kiểm tra:
đủ 3 phần, header alg/typ đúng, kid khớp fingerprint của public key
đưa vào, chữ ký khớp, `exp` chưa qua, card trong payload hợp lệ.
`verifyAgentCardJwsWithCardKey()` đối chiếu JWS với public key lấy
từ `card.signature` kiểu cũ.

### 2.3 Discovery qua cả hai well-known path

- Chuẩn A2A 1.0: `/.well-known/agent-card.json` (server phục vụ từ
  trước).
- Alias (v1.07): `/.well-known/agent.json` — server phục vụ **cùng
  một card, cùng chữ ký**; client thử path chuẩn trước, fallback sang
  alias khi server ngoài trả 404 ở path chuẩn.
- JWS: `GET /.well-known/agent-card.jws` → token compact,
  `Content-Type: application/jwt`; server không có signer → 404.
  Client đọc bằng `fetchAgentCardJws(baseUrl, publicKeyBase64)`.

### 2.4 Khóa ký trong Vault (`a2a/vaultSigning.ts`)

Key Ed25519 trước đây chỉ sống trong file PEM plaintext
(`a2a-signing-key.pem`). Nay có thêm đường Vault: namespace riêng
`'a2a'`, key `'signing-key'`, giá trị là PEM (Vault mã hoá AES-256-GCM
trước khi ghi đĩa nên PEM không nằm plaintext trong `vault.json`).

- `loadOrCreateVaultSigningKey(vault)` — đọc hoặc tạo mới + lưu.
- `rotateVaultSigningKey(vault)` — keyId đổi → client
  trust-on-first-use thấy key mới.
- `removeVaultSigningKey(vault)` / `hasVaultSigningKey(vault)` /
  `loadVaultSigningKey(vault)` (đọc, không tạo mới).
- PEM trong Vault hỏng → throw rõ ràng, không tự ghi đè.
- Server dùng keyPair như cũ (`createA2aServer({ signer })`) — không
  đổi API server. File PEM vẫn hỗ trợ (fallback cho test/CLI).

### 2.5 Registry agent local kiểu AGNTCY (`a2a/registry.ts`)

AGNTCY (Cisco Outshift, donate Linux Foundation 07/2025) là tầng
discovery/identity cho hệ multi-agent: agent đăng ký "tôi là ai, tôi
làm được gì", agent khác tìm theo capability rồi mới gọi. Registry
của open-bot chạy **local** (không server ngoài, không gửi gì đi):

- `register(card)` / `registerFromUrl(baseUrl)` — validate card,
  verify chữ ký (ghi `signatureOk` + `keyId`), nguồn
  `local`/`discovered`/`manual`.
- `search(query, filters)` — chấm điểm relevance: khớp tên +5,
  skill id +4, skill name/tag +3, mô tả +1, substring +1; lọc theo
  skill, streaming, push, trust, healthy-only.
- `healthCheckAll()` — fetch lại card từng agent, cập nhật health
  (`ok`/`unreachable`/`invalid-card`) + `lastSeenAt`.
- TTL + `pruneExpired()`; persistence file JSON
  (`a2a-registry.json`, ghi atomic, mode 0600).
- **Registry không tin tưởng agent.** Cờ `trusted` chỉ do user đặt
  ở UI. Tool `a2a_send` vẫn chỉ gọi agent user đã trust.

### 2.6 Task state machine có guard (`a2a/stateMachine.ts`)

`history.ts` đã có bảng chuyển trạng thái nhưng server tự gọi
`setState` rời rạc — chuyển sai chỉ ghi `legal: false` rồi đi tiếp.
`A2aTaskStateMachine` bọc một task:

- `transition(to)` — strict mặc định: chuyển bất hợp pháp throw
  `A2aIllegalTransitionError` (không đổi trạng thái, nhưng vẫn ghi
  transition `legal: false` vào lịch sử); `lenient: true` giữ hành
  vi cũ (chuyển tiếp + cảnh báo + event `illegal-transition`).
- Helper ngữ nghĩa: `start()`, `requestInput()`, `resume()`,
  `complete()`, `fail()`, `cancel()`, `reject()`,
  `applyRunnerResult()` (error → failed, needsInput →
  input-required, còn lại → completed + artifact text),
  `addArtifact()` (throw khi task đã terminal).
- Phát event `state-changed`/`artifact`/`illegal-transition` cho
  listener (SSE layer đăng ký). Server hiện tại chưa nối sang class
  này (tránh đụng code đang chạy) — sóng sau có thể nối mà không
  đổi wire format.

### 2.7 Cặp loopback thật (`a2a/loopback.ts`)

`startLoopbackA2aPair()` — server HTTP thật bind `127.0.0.1` cổng
ephemeral + client thật qua `fetch`, runner echo mặc định (đẩy 2
chunk tiến độ qua SSE). Dùng trong test end-to-end và demo/dev.
`http.server` expose server logic thật (cùng store task với HTTP
layer) — không tạo server thứ hai.

## 3. Endpoint tổng kết (server HTTP)

| Method + path | Trả về |
|---|---|
| `GET /.well-known/agent-card.json` | Agent Card JSON (có `signature` khi có signer) |
| `GET /.well-known/agent.json` | Cùng card trên (alias, v1.07) |
| `GET /.well-known/agent-card.jws` | JWS compact, `application/jwt` (404 khi không có signer) |
| `POST /` (JSON-RPC) | `message:send`, `message:stream` (SSE), `tasks/get/list/cancel`, `tasks/resubscribe`, push config |

| `GET /tasks/:id/events` | Resubscribe SSE |

## 4. Trust model

- Verify chữ ký chỉ chứng minh card khớp key đã ký (kid =
  fingerprint SHA-256 của public key SPKI DER). Key thuộc về ai là
  quyết định **trust-on-first-use** của user (xem
  `verifyAgentCardTrust` trong `signing.ts`).
- JWS `exp` mặc định 24h — client từ chối token hết hạn; server ký
  lại mỗi lần phục vụ nên token luôn mới.
- Registry/health check không bao giờ tự tin tưởng agent.

## 5. Giới hạn còn lại

- Server chưa nối sang `A2aTaskStateMachine` (vẫn `setState` nội
  bộ) — state machine mới dùng trong code mới + test; nối server
  là việc sóng sau.
- JWS Agent Card chưa có key rotation tự động theo lịch — rotate
  bằng tay (`rotateVaultSigningKey`) rồi user xác nhận key mới.
- Registry chỉ local (một máy); discovery liên máy (mDNS/DHT)
  chưa làm — AGNTCY đầy đủ có discovery phân tán, ở đây cố tình
  chỉ local theo hướng local-first.
- Không có UI view riêng cho registry/JWS trong sóng này — chỉ có
  chuỗi i18n + tool; view UI là việc của đội UI.
- Gemini live image không thử (key miễn phí quota ảnh = 0).

## 6. ACP — CHỈ CÒN LÀ MIGRATION NOTE

**ACP (Agent Client Protocol, IBM BeeAI, ra 03/2025) đã sáp nhập
vào A2A tháng 08/2025. ACP dừng phát triển độc lập, repo gốc
archived, doc IBM redirect sang A2A. Đừng thiết kế kiến trúc mới
quanh ACP.**

Trong open-bot, ACP chỉ còn ở hai chỗ:

1. `packages/core/src/a2a/acpAdapter.ts` — adapter cho agent ACP cũ
   (vd BeeAI) còn chạy: dịch A2A task → ACP session/prompt, gom
   update thành artifact. Giữ lại vì còn agent ACP cũ cần nối.
   Khi không còn agent ACP nào, xoá module này cùng `packages/core/src/acp/`.
   Câu chữ chuẩn nằm trong const `ACP_MIGRATION_NOTE` ở đầu file.
2. `packages/core/src/acp/*` — client/server ACP cũ (giữ nguyên,
   không mở rộng).

**Mọi tính năng agent↔agent mới viết bằng A2A v1.0 thuần.**
Migration ACP → A2A (cho agent cũ): giữ nguyên session/prompt
semantics, đổi transport sang JSON-RPC `message:send` + Agent Card
`/.well-known/agent-card.json` (ký JWS theo §2.2), task lifecycle
theo state machine §2.6, streaming artifact qua SSE thay vì ACP
`sessionUpdate` stream.
